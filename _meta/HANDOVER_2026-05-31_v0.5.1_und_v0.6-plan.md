## 3. Beantwortete Fragen des Anwenders (Feldbefunde)

1. **„Wie wird ein Skill (.md) hinzugefügt? Nur Text eintragen ergibt keinen Skill — ich muss importieren."**
   → **Richtig erkannt.** Aktuell trägt das Feld nur einen *Namen* in eine Liste; beim Kompilieren wird
   daraus eine **generische SKILL.md-Hülle** (`harness/templates.py:555 skill_files`) erzeugt — **kein echter
   Skill**. **v0.6 löst das:** echter **`.md`-Datei-Import** je Agent, Inhalt wird unverändert ins Harness-ZIP
   unter `.claude/skills/<name>/SKILL.md` geschrieben (Frontmatter name/description wird validiert).
2. **„Tags wie `pvm-validate`, `rubric-eval` — sind das Skills? Funktioniert das?"**
   → Ja, **Skill-Referenzen** (Claude-Code-Skills). Sie funktionieren bislang nur als Platzhalter (s. o.).
   v0.6 macht sie zu echten importierten Skills.
3. **„Risikobewertung über Dropdown; Ergebnis E×A; Erklärung fehlt; besser ‚Mitigations-Maßnahme'?"**
   → **Alles übernommen (v0.6):** Eintritt/Auswirkung als **Dropdown 1–5**, **live ‚= E×A → Ampel'**
   (grün <8 · gelb 8–14 · rot ≥15), **Scoring-Erklärung**, Label **„Maßnahme" → „Mitigations-Maßnahme"**.
   (Backend rechnet die Ampel schon korrekt aus E×A — nur Anzeige/Eingabe wird verbessert.)
4. **„Was soll die Fehlermeldung `--no-sandbox`? Repariere."**
   → **Kein App-Bug und nicht im Code behebbar.** Das ist eine **Chrome-Warnung**, weil der Browser mit dem
   Flag `--no-sandbox` gestartet wurde (typisch bei automatisiert gestartetem Chrome). Fix: Chrome **normal**
   starten (ohne das Flag). Bei echten Endnutzern erscheint der Balken nicht.
5. **„Aktivitäten komplett streichen; nur Meilensteine + Datum; keine Detailangaben; keine Personentage;
   pro Agent nur Tokenverbrauch."**
   → **Bestätigt und vollständig in den v0.6-Plan aufgenommen** (siehe §4).

**A) Aktivitäten + Personentage (effort_pt) vollständig entfernen**

## 6. Wichtige Betriebs-/Build-Regeln (aus dieser & früheren Sessions)

- **`tsc --noEmit` ≠ Prod-Gate.** Das Prod-Frontend-Image baut `next build` **inkl. ESLint**. Vor jedem Push
  lokal `next build` laufen lassen (in `$HOME`-Kopie, **nicht** aus Dropbox — SWC blockiert). v0.5.0-Deploy
  scheiterte genau daran (1 ESLint-Fehler `react/no-unescaped-entities`).
- **Quote-Fallen:** in JSX-**Text** keine rohen `"` (→ react/no-unescaped-entities); in JS-**String-Literalen**
  keine geraden `"` mitten im deutschen Text (bricht das Literal → SWC-Syntaxfehler). Typografische `„ "` nutzen.
- **Prod-API-Routen:** Prefix **`/v1/...`**; nur `/health` offen; OpenAPI/Docs in Prod aus → unautorisierte
  fachliche Pfade liefern 404 (kein Bug).
- **API-Pipeline für Tests:** `POST /v1/projects {title, owner_id}` → `PATCH …/understanding
  {project_type:"it"|"non-it", understanding_summary}` (**project_type ist Pflicht vor Gate 1!**) →
  `approve-understanding` → `guardrails/clear {proceed:true}` → `plan` → `milestones/done` →
  `approve-plan` → `harness`. (Aktivitäts-Endpunkte fallen mit v0.6 weg.)
  ⚠️ Deutsche Umlaute in inline-`curl --data` lösen „Invalid HTTP request" aus → JSON aus Datei (`--data @file`)
  oder Playwright `request` nutzen.
- **Lokaler Tabletop:** Backend `cd planner/api && source .venv/bin/activate && uvicorn app.main:app --port 8000`
  (In-Memory → Projekte flüchtig). Frontend: rsync nach `$HOME/aomp-build/planner`, `next dev -p 3000`,
  `NEXT_PUBLIC_API_BASE_URL=http://localhost:8000`. Browser über **localhost** (nicht 127.0.0.1 — CORS).
- **Guardrails:** `gh pr merge` auf main, Lesen von Prod-Secrets (`az containerapp secret show`) und Editieren
  von `.claude/settings.local.json` werden vom Auto-Klassifizierer geblockt — **der Anwender** führt sie aus.
