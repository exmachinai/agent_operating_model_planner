## 0. TL;DR — Auftrag

Mache die **33 kuratierten Skills im Harness auswählbar**. Heute: Live-App `0.6.0`; es gibt nur
pro-Agent-`SKILL.md`-Upload (v0.6). Der Katalog existiert als **Repo-Daten**, ist aber **nirgends
eingebunden** (kein Import, kein API-Endpunkt, keine UI). Ziel: Sobald der Harness die Agenten erkennt,
werden passende Skills **angeboten**, der Anwender **wählt** sie über einen Picker (Weltklasse-UX), Auswahl
landet auditierbar im Harness-ZIP. Umsetzung in 5 Meilensteinen (M1–M5), Backend zuerst.

## 1. Eckpfeiler (verbindlich, gelten ohne Rückfrage)

- **Trust-Infrastructure**, nicht Compliance-Software. Buyer-Promise „evidence-based, audit-ready".
- **Keine 100%-/Garantie-Claims.** Trust-Tier ist eine *Einstufung*, keine Garantie.
- **Kein „DACH".** Rechtsräume: `DE` · `EU27-Rest` · `UK` · `CH`. US-Nexus = Vendor-Layer.
- **Keine AEGIRA-eigenen Methoden-Skills (zgpm-*) in diesem Katalog** — separater `aegira-certified`-Strang.
- **Eindeutige Skill-Bezeichnung:** jede `catalog_id` folgt `^[a-z0-9-]+_skill$` (z. B. `ux-design_skill`).
  Davon getrennt der Upstream-`slug` (Standard, **kein** Unterstrich) = Ordnername/Frontmatter `name`.
- **AIMS** (ISO 42001 × CMMI) als Maturity; MITRE/GMS deprecated. Produktnamen eingefroren.
- **Kein Schreibzugriff auf Zone 2** (`00_CLAUDE_KNOWLEDGE_ARCHITECTURE/**`) — Safety-Guard aktiv.

## 3. Zielbild (kurz; Details in docs/15 §4)

Agenten erkannt (`defaults_for`) → `skills_for_agents(agent_ids)` liefert Empfehlungen → Picker bietet sie an
(`anthropic-vetted`/`world-top` vorselektiert; `community`/`experimental` sichtbar, nie Default, HITL/Gate) →
Auswahl wird kompiliert: Skill-Inhalt zur **Build-Zeit hydriert** (Lizenz + `content_sha256`), unverändert ins
ZIP unter `.claude/skills/<slug>/SKILL.md` + `.claude/skills/_manifest.json` (Audit).

## 5. API-Vertrag (konkret)

```
GET /v1/skills
  → 200 [CatalogSkill, …]                      # ganzer Katalog (33)

GET /v1/skills/recommended?agents=architecture-agent,reviewer-agent
  → 200 {
      "preselected": [CatalogSkill, …],         # trust_tier ∈ {anthropic-vetted, world-top}
      "offered":     [CatalogSkill, …]          # trust_tier ∈ {community, experimental}
    }
```
Prefix **`/v1`** (Prod: nur `/health` offen, OpenAPI aus → andere Pfade 404 ist kein Bug).
Agent-IDs sind exakt `CatalogAgent.id` aus `catalog.py` (z. B. `pmo-orchestrator`, `architecture-agent`).

## 6. Datenmodell `CatalogSkill` (Felder)

```
catalog_id: str        # ^[a-z0-9-]+_skill$  — eindeutige Bezeichnung (Anzeige/Audit)
slug: str              # Upstream-Ordner/Frontmatter name (^[a-z0-9-]{1,64}$, kein "_")
title: str
description: str       # Trigger-Beschreibung (≤1024), Progressive Disclosure
author: str            # frontmatter metadata.author
source: str            # Repo-URL bzw. "user-upload" / "internal:…"
trust_tier: SkillTrustTier
license: str | None
domain: str            # output|engineering|devops|data|security|design|research|methodology
project_types: list[str]   # ["it","non-it"]
subtypes: list[str]        # mappt auf catalog._IT_ALL/_NONIT_ALL
agent_ids: list[str]       # Brücke zu defaults_for (CatalogAgent.id)
version: str               # SemVer / "n/v"
released_at / updated_at: date | None
deprecated: bool
required_tools: list[str]
required_mcps: list[str]
model_tier: str | None
risk: "low"|"medium"|"high"
has_scripts: bool          # → Security-Gate
content_sha256: str | None # Integrität (Build-Zeit)
content: str | None        # bei Upload: unveränderte SKILL.md
```
Quelle der 33 Default-Werte: `harness/skill_catalog/_manifest.json`.

## 7. Build-/Betriebs-Regeln (aus früheren Sessions — beachten!)

- **`tsc --noEmit` ≠ Prod-Gate.** Prod-Frontend baut `next build` **inkl. ESLint**. Vor jedem Push lokal
  `next build` laufen lassen — in `$HOME`-Kopie, **nicht** aus Dropbox (SWC blockt). v0.5.0-Deploy scheiterte
  an 1 ESLint-Fehler (`react/no-unescaped-entities`).
- **Quote-Fallen:** in JSX-**Text** keine rohen `"` (→ no-unescaped-entities); in JS-**String-Literalen** keine
  geraden `"` im deutschen Text (bricht das Literal). Typografische `„ "` nutzen.
- **API-Pipeline für Tests:** `POST /v1/projects {title, owner_id}` → `PATCH …/understanding
  {project_type, understanding_summary}` (project_type Pflicht vor Gate 1) → `approve-understanding` →
  `guardrails/clear {proceed:true}` → `plan` → `milestones/done` → `approve-plan` → `harness`.
  ⚠️ Deutsche Umlaute in inline-`curl --data` → „Invalid HTTP request"; JSON aus Datei (`--data @file`) oder
  Playwright `request` nutzen.
- **Lokaler Tabletop:** Backend `cd planner/api && source .venv/bin/activate && uvicorn app.main:app --port 8000`.
  Frontend: rsync nach `$HOME/aomp-build/planner`, `next dev -p 3000`,
  `NEXT_PUBLIC_API_BASE_URL=http://localhost:8000`. Browser über **localhost** (nicht 127.0.0.1 — CORS).
- **v0.6-Philosophie nicht zurückdrehen:** keine Aktivitäten/Personentage wieder einführen.
