## 2. Was in v0.5 umgesetzt wurde (alles in Dropbox, getestet)

### Etappe 1 — Geführter Plan-Wizard + LLM-Vorschläge + Tools + Gesamtrisiko-Narrativ
Neuer Flow ersetzt die alte read-only Plan-Seite:
```
guardrails → /plan/milestones (6a) → /plan/activities (6b) → /plan (6c Ergebnis) → review → Gate 2 → harness
```
- **6a Meilensteine:** vorgeschlagen (LLM-first/Fallback), editierbar (Name/Datum), löschen/hinzufügen,
  **sortieren per Drag&Drop ODER ▲▼-Pfeile** (touch-tauglich). **DONE** schaltet 6b frei.
- **6b Aktivitäten:** je Meilenstein Vorschläge (Beschreibung/Aufwand editierbar, sortierbar) **plus
  abgeleitete Werkzeug-/MCP-Vorschläge** als Chips mit „?"-Klartext-Erklärung (annehmen/verwerfen).
  **DONE** schaltet 6c frei.
- **6c Ergebnis:** Gantt/RACI/Heatmap/Token/Auslastung **abgeleitet** + **qualitatives Gesamtrisiko-
  Narrativ** (`plan.risk_narrative`, Klartext — nicht nur „schlechteste Ampel gewinnt").
- **Gating:** `/activities` erst nach `milestones_done_at`, `/plan` erst nach `activities_done_at`
  (sonst Redirect in den offenen Schritt). 409 bei Edits nach DONE/Gate 2.
- **LLM-first mit Fallback:** `planning/llm_planner.py` ruft Foundry; ohne Creds/bei Fehler →
  deterministischer `zgpm_composer` (App bricht nie). PVM-Matrix + Risiken werden **im Hintergrund**
  konsistent gehalten (`recompute`), der Anwender editiert nur das Fachliche.

### Etappe 1G — Werkzeug-/MCP-Bindung je Agent (Harness, Schritt 8)
- Neues Revise-Command **`tool`** (add/remove je Agent), analog `skill`.
- Neuer Endpunkt **`GET /plan/accepted-tools`** (akzeptierte Tools aus 6b, dedupliziert).
- Canvas-Detail-Panel: gebundene Tools entfernbar (×), Katalog-Vorschläge als „+"-Chips,
  High-Risk rot. Touch: Palette-Karten **antippbar** (zu Stage 1) statt nur Drag.

### Etappe 2 — Mobile/UX (Desktop + iPhone 15 Plus)
- `tokens.css`: Breakpoints (sm640/md768/lg1024) + Utility-Klassen
  `.aegira-shell / -actions / -cols-2 / -scroll-x / -canvas-grid / -hide-sm / -only-sm`
  (Inline-Styles können kein `@media` → Klassen). **`overflow-x: clip` auf `html, body`**
  (Plan-Overflow-Fix). Touch-Min 44px.
- `layout.tsx`: Viewport `maximumScale 5 / userScalable` (iOS-A11y).
- `ui.tsx`: Button `minHeight 44`, Input `minHeight 44 + fontSize 16` (kein iOS-Auto-Zoom).
- `PageShell`: `.aegira-shell` (fluid < md, 880px ≥ md).
- `PlanViews`: Gantt/RACI/Heatmap auf `.aegira-scroll-x`.
- `HarnessCanvas`: `.aegira-canvas-grid` (Palette mobil über Lanes).
- `understanding`: Radios flex-wrap+44px, Action-Bars `.aegira-actions` (stapeln mobil).

## 7. Schritt-Flow & API-Vorbedingungen (v0.5, sonst 409/422)

`createProject` → `PATCH /understanding` → `POST /approve-understanding` (Gate 1) →
`POST /guardrails/clear {proceed:true}` → `POST /plan` (LLM/Fallback) →
`POST /plan/milestones/op` (add/update/delete/reorder) → `POST /plan/milestones/done` →
`POST /plan/activities/op` (inkl. `tool_id`/`tool_accepted`) → `POST /plan/activities/done` →
`POST /approve-plan` (Gate 2) → `POST /harness` → `POST /harness/revise` (`tool`-Command u.a.) →
`POST /approve-harness` (Gate 3).
