# v0.6 — Meilenstein-zentrierter Plan (Aktivitäten & Personentage entfernt)

> Status: **Spezifikation/Plan** (vor Umsetzung). Sprache Deutsch, Code englisch.
> Auslöser: Feldbefund — Aktivitäten sind nicht nötig, da Agenten sie autonom übernehmen;
> Personentage sind im agentischen Betrieb keine sinnvolle Einheit. Kosten = Token je Agent.

## 1. Entscheidung (vom Anwender bestätigt)

- **Aktivitäten entfallen vollständig** — keine Eingabe, keine Detailangabe, keine 3-Default-Aktivitäten.
- **Personentage (effort_pt) entfallen vollständig** — auch „Auslastung je Agent (PT)".
- **Schritt 6b „Aktivitäten & Werkzeuge" entfällt** — Flow: `6a Meilensteine → 6c Ergebnis`.
- **Werkzeug-/MCP-Bindung** passiert nur noch im **Harness (Schritt 8) je Agent** (existiert bereits).
- **Gantt** = Meilenstein-Gantt (Balken bis Zieldatum, Farbe = Risiko-Ampel) — keine Aktivitätsfenster.
  Start = Vorgänger-Termin (sonst Termin − 14 Tage), Ende = Zieldatum.
- **Kosten** = **Token-Schätzung je Agent** (`plan.token_budget`, bleibt; nicht mehr aus PT abgeleitet).
- **Hinweis im UI:** „Aktivitäten werden autonom von den Agenten übernommen — keine manuelle Detailplanung nötig."
- **Schema-Bruch bewusst** (sauberer Schnitt): `Activity`/`effort_pt` raus aus Schema + Code. In-Memory-Pläne
  sind flüchtig; Cosmos-Altdaten werden separat behandelt (kein Migrationscode in v0.6).

## 2. Backend-Änderungen (`planner/api/app`)

- `schemas/plan.py`:
  - **entfernen:** `Activity`, `ActivityPatch`, `ActivityOp`, `ToolSuggestion` (war nur an Aktivität),
    `Milestone.activities`, `effort_pt` überall, `PlanRevisionRequest.activities`.
  - `Milestone` = `id, name, phase_id, stream_code, planned_date, predecessors, ampel, responsibilities, mrl`.
- `planning/zgpm_composer.py`:
  - keine Aktivitäten generieren; `apply_activity_ops`/aktivitätsbezogene Recompute-Teile entfernen.
  - Gantt-relevante Ableitung nutzt `planned_date` (Start = Vorgänger-Datum bzw. planned_date − Default-Fenster).
  - Token-Budget je Agent bleibt; **PT-Auslastung-Berechnung entfernen**.
- `schemas/project.py`: `activities_done_at` **entfernen** (nur noch `milestones_done_at`).
- `routers/plans.py`: Endpunkte **`/plan/activities/op`, `/plan/activities/done`, `/plan/accepted-tools` entfernen**;
  Gating: `/plan`(Ergebnis) erst nach `milestones_done_at` (nicht mehr `activities_done_at`).
- `harness/templates.py` + `harness/compiler.py`: Stellen, die `activities`/`effort_pt` lesen, auf Meilenstein-Ebene umstellen.
- Tests: `tests/test_plan_wizard.py` (6b-Teile raus), übrige anpassen. Ziel: `pytest` grün.

## 4. Risiko-Editor verbessern (MilestoneEditor / Risiko-Block)

- Eintritt + Auswirkung als **Dropdown 1–5** (statt freier Zahl).
- **Live-Ergebnis „= E×A → Ampel"** anzeigen (grün <8 · gelb 8–14 · rot ≥15).
- Kurze **Scoring-Erklärung** unter dem Block.
- Beschriftung **„Maßnahme" → „Mitigations-Maßnahme"**.

## 5. Echter SKILL.md-Import (Harness, Schritt 8)

- Freitext-Skill-Feld je Agent **ersetzen** durch **`.md`-Datei-Upload**.
- Hochgeladener Inhalt wird gespeichert (neues Feld/Command, z. B. `skill` mit `content`) und beim Kompilieren
  **unverändert** unter `.claude/skills/<name>/SKILL.md` ins ZIP geschrieben — statt der generischen Hülle in
  `templates.skill_files`. Validierung: Frontmatter `name:`/`description:` muss vorhanden sein.
- Fallback: Für die im Katalog kuratierten Skills bleibt die bekannte Beschreibung; nur importierte überschreiben.
