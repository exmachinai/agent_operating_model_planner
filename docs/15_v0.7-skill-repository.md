## 0. Management Summary (Governing Thought)

**Leitsatz:** AEGIRA braucht ein **kuratiertes, klassifiziertes Skill-Repository als Trust-Layer über den
Agenten** — nicht eine offene Skill-Sammlung. v0.6 hat die *Import*-Lücke geschlossen (echte `SKILL.md` statt
generierter Hülle); v0.7 schließt die **Kuratierungs-, Klassifizierungs- und Auswahl-Lücke**: Sobald der
Harness erkennt, welche Agenten ein Vorhaben braucht, **bietet** er die dazu passenden, geprüften Skills aktiv
an, der Anwender **wählt** sie über eine Weltklasse-UX, und nur Skills mit dokumentierter Herkunft und
Vertrauensstufe landen im Harness-ZIP.

**SCQ.**
- **Situation:** Der Agentenkatalog erkennt benötigte Agenten bereits automatisch (`defaults_for`). Jeder Agent
  trägt Skill-Slugs.
- **Complication:** Diese Slugs sind nur Strings; ohne Import kompilieren sie zu generischen Hüllen. Es gibt
  keinen Katalog, keine Klassifizierung, kein aktives Angebot, keine Auswahl-UI, keine Vertrauensstufe und
  keine Herkunfts-/Integritätsprüfung. Das verletzt die Buyer-Promise „evidence-based, audit-ready".
- **Question:** Wie wird ein weltklasse, klassifiziertes, vertrauensgeprüftes Skill-Repository so eingebaut,
  dass passende Skills automatisch angeboten und vom Anwender ausgewählt werden — ohne die Trust-Garantien zu
  verwässern?
- **Answer (Hypothese):** Ein `CatalogSkill`-Modell (analog `CatalogAgent`) mit vier
  Klassifizierungs-Achsen + Trust-Tier, drei kuratierten Quellen (Anthropic-gevettet, weltbeste recherchiert,
  AEGIRA-eigen-Upload), einem Agent→Skill-Matching und einer faceted Selektions-UX. Kuratierung **zur
  Build-Zeit**, Auswahl mit HITL — kein Live-Marketplace-Abruf im Kunden-Harness.

**Drei Kernbotschaften (Pyramide):**
1. **Klassifizieren statt sammeln** — vier Achsen (Autor+Trust, Domäne+Subtyp, Version+Datum, technische
   Properties) machen Skills auffindbar, vergleichbar und auditierbar.
2. **Anbieten statt suchen lassen** — das Matching nutzt den bestehenden Agentenkatalog: erkannte Agenten →
   vorselektierte Skill-Empfehlungen.
3. **Vertrauen ist das Produkt** — Trust-Tier + Herkunft + Integrität + Security-Gate sind der eigentliche
   Mehrwert; sie sind die AEGIRA-Differenzierung gegenüber offenen Marktplätzen.

## 2. Komplikation — die Lücke (MECE)

Die Lücke zerfällt überschneidungsfrei in fünf Teile:

1. **Daten:** Skills haben keine Metadaten → nicht klassifizier-, filter- oder vergleichbar.
2. **Herkunft/Vertrauen:** Keine Quelle, kein Trust-Tier, keine Integrität → nicht audit-ready.
3. **Matching:** Keine Brücke „erkannter Agent → empfohlene Skills".
4. **Interaktion:** Kein Picker, keine Facetten, keine Vorselektion, keine Vorschau.
5. **Governance:** Kein Security-Gate für importierte/fremde Skills (Skills können Skripte mitführen →
   Supply-Chain-/Injection-Risiko).

---

## 3. Leitfrage & Hypothese

> **Leitfrage:** Wie liefert AEGIRA passende, geprüfte Skills automatisch zum erkannten Agenten-Set und lässt
> den Anwender sicher auswählen — auditierbar und ohne Trust-Verwässerung?

**Hypothese:** Lösbar durch (a) ein klassifiziertes `CatalogSkill`-Modell, (b) ein deterministisches
Agent→Skill-Matching auf Basis des bestehenden Katalogs, (c) eine faceted Auswahl-UX mit Vorselektion und
Vorschau, (d) ein Trust-/Security-Gate vor Aufnahme ins ZIP. Diese Hypothese strukturiert §4.

## 4. Zielbild (Answer) — MECE-Zerlegung

### 4.1 Datenmodell `CatalogSkill` (alle vier Klassifizierungs-Achsen)

Analog zu `CatalogAgent`. Neues Modul `harness/skill_catalog.py` + Schema in `schemas/harness.py`.
Die Achsen bilden 1:1 auf den offenen `SKILL.md`-Standard ab (Frontmatter `name`/`description`, optional
`metadata.author`/`version`/`license`) und ergänzen ihn um AEGIRA-Trust-Felder.

```python
class SkillTrustTier(str, Enum):          # Achse 1b — Vertrauensstufe
    anthropic_vetted = "anthropic-vetted" # offiziell von Anthropic, höchstes Vertrauen
    aegira_certified = "aegira-certified" # AEGIRA-eigen, intern geprüft
    world_top = "world-top"               # öffentlich, kuratiert + manuell gevettet
    community = "community"               # öffentlich, ungeprüft (nur sichtbar, nicht vorselektiert)
    experimental = "experimental"         # in Erprobung, nie Default

class CatalogSkill(BaseModel):
    # Identität
    catalog_id: str                       # AEGIRA-eindeutige Bezeichnung, Konvention "<funktion>_skill"
                                          #   (z. B. "ux-design_skill"); ^[a-z0-9-]+_skill$ — Anzeige/Referenz
    slug: str                             # Upstream-Ordnername .claude/skills/<slug>/, ^[a-z0-9-]{1,64}$
    title: str
    description: str                      # Trigger-Beschreibung (≤1024), Progressive Disclosure
    # Achse 1 — Autor + Trust
    author: str                           # frontmatter metadata.author (Anthropic / exmachinAI / <handle>)
    source: str                           # "anthropic-skills" | "aegira" | "<repo-url>" | "user-upload"
    trust_tier: SkillTrustTier
    license: str | None = None
    # Achse 2 — Domäne + Subtyp-Mapping
    domain: str                           # z. B. "engineering", "data", "legal", "design", "methodology"
    project_types: list[str]              # ["it","non-it"]
    subtypes: list[str]                   # mappt auf catalog._IT_ALL / _NONIT_ALL
    agent_ids: list[str]                  # empfohlen für diese Agentenrollen (Brücke zu defaults_for)
    # Achse 3 — Version + Datum
    version: str                          # SemVer aus frontmatter metadata.version
    released_at: date | None = None
    updated_at: date | None = None
    deprecated: bool = False              # Deprecation-Muster wie MITRE/GMS
    # Achse 4 — technische Properties
    required_tools: list[str] = []        # least-privilege Tools (Typ + Risk wie ToolSpec)
    required_mcps: list[str] = []         # benötigte MCP-Server (Registry-Abgleich)
    model_tier: str | None = None         # opus/sonnet/haiku, falls relevant
    risk: Literal["low","medium","high"] = "low"
    has_scripts: bool = False             # trägt der Skill ausführbaren Code? → Security-Gate
    # Integrität / Audit
    content_sha256: str | None = None     # Supply-Chain-Integrität (audit-ready)
    content: str | None = None            # bei Upload: unveränderte SKILL.md (wie SkillImport)
```

> `SkillImport` (v0.6) bleibt als Upload-Pfad und wird zum Spezialfall „`trust_tier=community` +
> `source=user-upload`" — d. h. v0.7 ist **abwärtskompatibel** und additiv.

### 4.2 Sourcing & Vetting (drei Quellen, ein Trust-Modell)

| Quelle | Trust-Tier (Default) | Aufnahme-Pfad | Pflege |
|---|---|---|---|
| **Anthropic-Skills** (`anthropics/skills`, installierte Plugin-Skills: `docx`, `pptx`, `data:*`, `engineering:*`, `legal:*`, `design:*`, `pdf`, `xlsx`, `skill-creator`, `mcp-builder`, `prompting-best-practices` …) | `anthropic-vetted` | kuratiertes Seed-File `skill_catalog.py` | bei Plugin-Update |
| **Weltbeste, recherchiert** (öffentliche Top-Skills, z. B. `code-reviewer`, `git-commit-writer`, `readme-generator`) | `world-top` (erst nach manuellem Vetting) | kuratierte Aufnahme mit `source`-URL + `content_sha256` | quartalsweise Review |
| **AEGIRA-eigene Methoden-/Risiko-Skills + Ad-hoc-Uploads** (separater Strang, hier nicht enumeriert) | `aegira-certified` (intern) / `community` (Ad-hoc-Upload) | zentral katalogisiert statt bare-slug; Upload wie v0.6 | bei Bedarf |

**Vetting-Kriterien (Aufnahme als `world-top`/`aegira-certified`):** gültiges Frontmatter (`name`/`description`),
klare Single-Responsibility, keine zu breite Trigger-Beschreibung, least-privilege Tools, kein verdeckter
Netzwerk-/Schreibzugriff, dokumentierte Herkunft + Lizenz, `content_sha256` hinterlegt, Security-Review bei
`has_scripts=true`. **Kein** Skill wird als „100 % sicher" deklariert — Trust-Tier ist eine *Einstufung*, keine
Garantie (Eckpfeiler).

### 4.3 Agent→Skill-Matching & aktives Angebot

Deterministisch auf Basis des bestehenden Katalogs:

1. `defaults_for(project_type, subtype)` liefert das Agenten-Set (existiert).
2. Neue Funktion `skills_for_agents(agents, project_type, subtype)` schneidet den Skill-Katalog auf
   `agent_ids ∩ gewählte Agenten`, gefiltert über `project_types`/`subtypes`, sortiert nach Trust-Tier.
3. Ergebnis: **Empfehlungsliste** je Agent — `anthropic-vetted`/`aegira-certified` **vorselektiert**,
   `world-top` angeboten, `community`/`experimental` nur auf Wunsch sichtbar, nie vorselektiert.

### 4.4 Selektions-UX (Weltklasse-UI) — explizit gefordert

Designprinzipien (konsistent zu `docs/05_ux-ui-best-practices.md`, mobile-first, Touch ≥44px, A11y):

- **Faceted Browser:** linke Filterleiste über alle vier Achsen (Autor/Trust-Tier, Domäne/Subtyp, Version/Datum,
  technische Properties: Tools/MCPs, Modell-Tier, Risk). Volltext-Suche über Titel + Trigger-Beschreibung.
- **Trust-First-Visualisierung:** farbcodierte **Trust-Badges** (anthropic-vetted, aegira-certified, world-top,
  community, experimental) + Risk-Ampel je Skill-Karte — Vertrauen ist sofort sichtbar.
- **Progressive Disclosure:** Karte zeigt zuerst nur `title` + `description` (= das, was der Agent zur
  Trigger-Entscheidung sieht); Aufklappen zeigt Frontmatter, Tools/MCPs, Version/Datum, Herkunft, `sha256`,
  und eine **read-only SKILL.md-Vorschau** (Markdown-Render).
- **„Empfohlen für deine Agenten":** oben eine vorselektierte Sektion (Mehrfachauswahl-Checkboxen), gruppiert je
  Agent; darunter „Weitere passende Skills" und „Alle durchsuchen".
- **Multi-Select + Konfliktauflösung:** gleiche `slug` aus zwei Quellen → Hinweis + Versionsvergleich; Anwender
  entscheidet (HITL). Fehlende `required_mcps` → Warnbanner mit Registry-Verweis (keine stille Annahme).
- **Upload-Inline:** „+ Eigene SKILL.md" im selben Flow; Frontmatter-Validierung live; landet als
  `community`/`aegira-certified`.
- **Audit-Sichtbarkeit:** „Diese Auswahl wird im Harness-ZIP dokumentiert (Skill, Version, Quelle, sha256)" —
  zahlt direkt auf „audit-ready" ein.
- Optionaler interaktiver Mockup (HTML) wird auf Wunsch separat geliefert.

### 4.5 Kompilierung (ins Harness-ZIP)

`templates.skill_files` wird erweitert: ausgewählte `CatalogSkill` werden — wie heute `imported_skills` —
**unverändert** nach `.claude/skills/<slug>/SKILL.md` geschrieben (kuratierter Inhalt statt generierter Hülle).
Zusätzlich entsteht ein **`.claude/skills/_manifest.json`** (Slug, Version, Autor, Trust-Tier, Quelle, sha256)
als Audit-Artefakt. Der **Constitution-Safety-Guard** bleibt: kein Write nach Zone 2.

### 4.6 Governance / Constitution-Alignment

- **Security-Gate:** `has_scripts=true` oder `trust_tier ∈ {community, experimental}` → HITL-Freigabe + Hinweis
  vor Aufnahme (Trust-Layer, analog High-Risk-Tools).
- **Air-Gap/Reguliert (DE/EU27-Rest/UK/CH):** **kein** Live-Marketplace-Abruf im Kunden-Harness; Kuratierung
  passiert zur Build-Zeit im Planner. US-Nexus bleibt Vendor-Layer.
- **Methodentreue:** AEGIRA-Skills bleiben ZGPM/AIMS-orientiert; MITRE nur als Tiefenanalyse-Skill, nie Default.
- **Marken:** keine PwC/MITRE/GMS-Suggestion; Produktnamen (AI Navigator/Guardian/Commander) unverändert.

## 5. Architektur-Entscheidungen (ADR-kurz, Trade-offs)

1. **Build-Zeit-Kuratierung statt Live-Marketplace.** *Pro:* Air-Gap, Reproduzierbarkeit, Audit. *Contra:*
   Manuelle Pflege. → **Gewählt** (Trust schlägt Bequemlichkeit).
2. **`CatalogSkill` zentral statt Slugs an Agenten.** *Pro:* Klassifizierung/Audit. *Contra:* Migration der
   `CatalogAgent.skills`. → **Gewählt** (Slugs werden zu Referenzen auf `slug`).
3. **Trust-Tier als Einstufung, nicht Garantie.** Eckpfeiler-konform (keine 100%-Claims).
4. **Additiv zu v0.6.** `SkillImport` bleibt; v0.7 bricht kein Schema (im Gegensatz zu v0.6). Minor-Sprung.

## 6. Ergänzungen (was im Auftrag fehlte — bewusst hinzugefügt)

1. **Herkunft + Integrität** (`source`, `content_sha256`) — Supply-Chain-Trust; Kern der Buyer-Promise.
2. **Security-Gate für Skripte/ungeprüfte Skills** — Skills können Code mitführen (Injection-Risiko).
3. **MCP-Abhängigkeiten je Skill** (`required_mcps`) + Registry-Abgleich — sonst „funktioniert nicht".
4. **Versionierung, Deprecation & Update-Hinweise** — wie MITRE/GMS-Deprecation, gegen Skill-Drift.
5. **Lizenz-/Compliance-Feld** für Dritt-Skills — rechtssicher in DE/EU27-Rest/UK/CH.
6. **Audit-Manifest im ZIP** (`_manifest.json`) — macht die Auswahl nachweisbar (audit-ready).
7. **Konfliktauflösung bei doppelten Slugs** + Versionsvergleich.
8. **Telemetrie-Hook (optional, opt-in)**: welche Skills wie oft gewählt → Pflege-Priorisierung.
9. **Deutsche Lokalisierung** der Katalog-UI (Doku-Hauptsprache).
10. **Abwärtskompatibilität**: bestehende Slugs werden auf Katalog-Einträge gemappt, keine Bruchstelle.

## 7. Anti-Scope (bewusst ausgeschlossen)

- **Kein** Live-Abruf eines externen Marktplatzes im Kunden-Harness (Security/Air-Gap).
- **Keine** Auto-Installation von `community`/`experimental`-Skills ohne HITL.
- **Keine** Auto-Ausführung importierter Skills ohne Security-Gate.
- **Kein** Aufbau einer eigenen Skill-Hosting-Plattform/Marktplatz durch AEGIRA.
- **Keine** Skills für Plattformen außerhalb `target_platform` (bestehende Skill-Mapping-Regel).
- **Keine** Wiedereinführung von Aktivitäten/Personentagen (v0.6-Entscheidung).
- **Keine** „100 % geprüft/sicher"-Claims; **kein** „DACH"; **keine** PwC/MITRE/GMS-Marken.
- **Kein** Schreibzugriff auf Zone 2 (`00_CLAUDE_KNOWLEDGE_ARCHITECTURE`).
- **Keine** automatische Skill-Generierung durch das Modell als Default (nur kuratiert/Upload).
